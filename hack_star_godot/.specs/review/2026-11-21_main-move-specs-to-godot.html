Concepts glossary

Architecture document
A text describing where screens, rules, models, saves, rooms and tests live. S13 makes hack_star_godot/docs/architecture.md the reference that every later spec reads and keeps up to date.
Back button
A control returning to the previous or home screen. Named here so its look is part of the shared theme, matching S10 of the same spec.
Branch link
A GitHub blob URL pinned to a branch name. It works while the branch exists; spec 18 is closed only there, so D6 chose it (finding 7).
Bug turned into behaviour
A Python bug that cannot happen in Godot is kept as a statement of the right behaviour, so a test still guards it instead of silently dropping it.
CANYON arena
The single 30 × 24 arena of the Python game. The fact is kept because Worlds turns today's arena into the first free world; in Godot that arena comes from specs 01, 06 and 07.
Compatibility renderer
Godot's OpenGL-based renderer that also runs in WebGL 2. Listed because spec 01 chose it so the web export works on iPad Safari.
FastAPI
The Python web framework of the existing server/ folder. The question is whether the Godot game reuses it for rooms and hack codes instead of building networking in Godot.
GDScript
Godot's own Python-like scripting language. S12 fixes it as the language of the Godot game, as already decided by spec 01.
git-ignored folder
A path listed in .gitignore, so its files are never committed. S36 uses it to keep music on each developer's computer only.
Godot documentation statement
The same requirement pointed at hack_star_godot/README.md and docs/architecture.md instead of the root documents of the Python game.
Godot editor / desktop run
Running the project from the editor or as a desktop build gives file access to the project folder, which the suggestion relies on.
GUT
Godot Unit Test, the test framework added by spec 01. Later specs write their tests with it instead of pytest or Vitest.
Moved from
The link back to the original Python + Svelte spec, its history and its plan, which stay in the root .specs/.
npm run dev
The Vite development server of the Svelte UI. S34 depended on it, which is why it is struck for the Godot game.
Open question (spec-nx)
An undecided point in Part 1. The plan stage refuses a spec with open questions, so this blocks PLAN: of spec 03 until the author answers it.
Open question with owner
An open question tagged with who answers it. Q3 blocks PLAN: of 14 and defers to the same question in 03, so it is decided once.
Order dependency
Spec 12 is built before 13 (S2), so it may not rely on fighter types; the sentence makes that explicit instead of "if it is done first".
PLAN: command
The kit command that writes Part 2 (Steps, decisions). S0 says the check and any revision must happen before it.
Portrait / landscape layouts
Screen orientations. Godot containers and anchors must adapt to both, which S12 makes a property of the foundation rather than of each screen.
Replacement marker
The fixed S7 wording that links a struck statement to its successor, so a reader sees what changed and why without the original.
REQUIREMENTS: command
The kit command that writes or revises Part 1 of a spec. Here it is the way to change the assumed answers S9–S11 later.
S0 — Check with the Godot game
The first statement of every moved spec. It forces a check of all statements against the Godot game before PLAN:, so Python-only assumptions are revised first.
Same Wi-Fi only
Devices talk over the local network. S8 keeps this, which still assumes a server on that network — exactly what Q3 leaves open.
Single-threaded web export
A Godot web build that needs no SharedArrayBuffer and so no special server headers. Named so later specs do not assume threads.
Spec 01 D13
The decision of spec 01 that music goes to hack_star_godot/assets/music/, inside the project because Godot only imports files there.
Status words
The README tracks to move / requirements / planned / implemented / closed for each spec; S11 asks it to be updated on every status change.
Strikethrough
Markdown ~~text~~ draws a line through text. Here it keeps the Python + Svelte statement readable (S7: replaced, not hidden) while marking it as not valid for the Godot game.
UI foundation
The shared look and navigation that every screen reuses. In Godot this is usually a Theme resource plus one scene-switching helper; S12 asks for it once, in spec 04.
Web export sandbox
A Godot game exported for the web runs in the browser sandbox and cannot write the computer's files. That is why Q1 is needed.
