Summary

Spec 16 fixes the reported bugs that can happen in the Godot game as built: INFINITY and OPENSESAME now last 3 days and turn off by themselves (POWER22 for ever), the hack screen shows the time left, a fighter locked again is never the chosen or the played one, and the web game keeps one save that all tabs share, merged on write and read when a tab comes back to the front. Range 235f93c..dfb85cb (this spec's commits only, from the plan commit 383f81c; the branch carries specs 03–08 and 16).

  • The time rules are pure (Hacks.duration_seconds, until_for, is_expired, time_left_text) and the game reads time through a replaceable clock, so every rule is tested without waiting.
  • The save goes to version 3 (each hack with its end time, and a revision); a spec 05 or 08 save keeps its hacks and progress, and its timed hacks get 3 days from the first start.
  • Turn all hacks off and a hack running out now replace a chosen fighter that is locked again; a running match gives its trophies to the fighter it started with.
  • Two tabs: a hack from tab 2 is no longer lost when tab 1 saves (record block two-tabs); 386 of 386 tests pass, lint is clean, server/ and ui/ are unchanged.
  • Five findings, none Blocking: a hack turned off in one tab can come back through another tab's merge (plan decision), the fighter screen misses trophies from another tab, and the expiry timer and focus triggers have no test.

Recommendation: Approve with follow-ups — no Blocking finding; findings 2–5 to fix now, 1 needs a plan decision.

Author Q&A

Why does the game not read the durations the server sends?
D1: the migration of a version 1 or 2 file and a game start without the server need them, so Hacks holds the same numbers as the server's duration_seconds (72 h or none); the comment in hacks.gd and the README say to keep the two equal.
What happens to what was gained while a hack was on?
Nothing is taken (S19, D3): a hack never writes into the progress, so trophies, power levels, unlocked, credits and skins stay; only the chosen fighter changes when it is locked again (D4, record block hack-expiry; test_hack_expiry.gd).
How do two tabs agree on one save?
D6, D7: the web save is one localStorage item every tab reads and writes. Each save first merges a newer stored revision (hacks a union with the later end, unlocked a union, trophies and power levels the higher; credits, choice and skins this tab's); a tab coming to the front reads a newer save (sync_from_store). See finding 1 for a hack turned off in one tab.
Was the two-tab case checked in a real browser?
Partly (Step 4 Notes): headless Chromium with the web export and the hack server; a ?hack=INFINITY link in tab 2 showed Credits ∞ in tab 1 when it came to the front. A match won in tab 1 was not driven; it stays with the author with the device play-test (Deferred Items).

Concepts glossary

Revision counter
A whole number every save increases; a stored number above the tab's own means another tab wrote since this tab last read, so the merge runs only then.
Signal
A Godot signal lets the screens refresh without GameState knowing them; here it tells them that another tab's progress arrived.
Expired check
until != FOREVER and until <= now; a stored hack that already ended is not brought back by the merge.
maxi
The integer maximum; the later end of the same timed hack wins, so entering a code again in another tab keeps its new 3 days.
Application focus notification
Sent to every node when the game window gets the focus from the operating system; here it re-reads the store when the player comes back.
JavaScriptBridge callback
Wraps a GDScript method as a JavaScript function; the object must be kept (_visibility_callback) or the browser calls a freed function.
visibilitychange
The page event fired when a browser tab is hidden or shown; on visible the tab syncs, as S4 asks (a hidden tab does not have to update).
End time
now + 3 days for a timed hack, 0 (FOREVER) for a for-ever hack; computed from the replaceable clock so tests move time without waiting.
Dictionary.get with a default
Returns the default when the key is missing; a hack without an end time counts as for ever and is never removed by mistake.
is_unlocked
The saved unlocked list or the unlock_all hack (Hacks.is_fighter_unlocked); once the hack is gone, only the saved list counts.
Version guard
A file written by a newer build is not read at all, so an old build never misreads fields it does not know.
Migration from now
Old files have no end times; giving each hack now + 3 days follows S16 (codes active when this version first opens get their 3 days from that moment).
Cut to the maximum
mini takes the smaller end: the saved one, or 3 days from now when the saved one lies further ahead.
localStorage
The browser's synchronous key-value store of one address, shared at once by all its tabs; read through JavaScriptBridge.get_interface("localStorage").
FileAccess
Opens (and empties) the file; it is closed and flushed when the last reference goes away at the end of the function.
warning_ignore
Silences GDScript's warning for integer division on this function only; the division by HOUR_SECONDS is meant to round down.
Rounding down
Integer division drops the remainder, so 59 minutes count as 0 hours and the text says "Less than 1 hour left".
Snapshot at start
The fighter is read once in _ready; the end of the match never reads GameState.selected_fighter again, as D4 asks.
