Summary

Created fighters get more parts (five heads and bodies, three hands and legs) and up to five free skins of their own; saves move to version 7 and still load every older save. A typed account rename is no longer lost, the game asks the browser to keep its saves and warns once when saving is blocked. Music plays in matches with an on/off switch; tracks are chosen per developer on a hidden developer page and never committed, and the About panel credits them with links to their source and licence.

  • 15 objects changed: 5 screens, 4 game rules / outputs, 2 settings, 2 messages, 1 save format, 1 dev-only API.
  • Older saves, options and the 16-character look id keep working; a friend on the previous version sees a new-part fighter in its default look.
  • Checks: 6 pass · 2 n/a · 1 fail; findings: 0 blocking, 2 should-fix, 1 nit.
  • Good: every new rule has unit tests (267 UI, 45 server), the look id stays backward compatible, and music never enters the repository.
  • Screens with music use made-up example tracks, so no real track is named here.

Recommendation: Approve with follow-ups — limit the dev server's GET requests to this computer (finding 1); real-device checks are in spec 5.

Author Q&A

Why is no music in the repository, while the game plays music?
To publish no third-party music. Each developer chooses tracks locally; the build includes only what that developer chose, and the About panel credits exactly those tracks (S32, D16).
Is the developer code a security control?
No. It is the QR code M6D2 and is in the public source; it only keeps kids out. The music tools that write files run only under npm run dev and only from the same computer.
Can a malformed local list break the game?
No. parseCandidates and the tracks loader drop entries with a bad id, file name or licence, and a byte-order mark is accepted.

Concepts glossary

Non-capturing group
A regex group (?:…) that groups alternatives without capturing. Here it lets one pattern accept both the 16- and the 18-character look ids.
Compiled regex
re.compile builds the pattern once at import. The room code reuses it for every join message instead of parsing the pattern each time.
Backward-compatible encoding
Writing the old format whenever the data fits it. Looks without new parts keep the 16-character id, so friends on the previous version still draw them.
RegExp.exec
exec returns the match with its groups, or null. Here the empty groups ()() keep group numbers equal for both id lengths.
Defaulted migration field
A field missing in older saves gets a default while parsing. Hands and legs default to 0, the body's own, so old looks stay the same.
Type predicate
A TypeScript return type value is T: when the function returns true, the checker treats the value as T. It validates saved JSON before use.
Bounded id slots
Ids s1…s5 are reused after a delete, so the limit of five holds and ids stay short in room messages.
Discriminated union
A union of object types told apart by a literal field (ok). Callers must check ok before reading progress, so a refused add cannot be used by mistake.
Commit on leave
Saving pending input when the user leaves the field, not only on the Save button. Closing the panel or picking another account keeps the typed name.
Callback prop
onClose is a function the parent passes in (a Svelte 5 callback prop); the panel calls it only after the typed name is saved.
Persistent storage
navigator.storage.persist() asks the browser not to clear this site's storage under pressure or after inactivity (Safari's 7-day rule).
Svelte store
A writable store holds a value that components subscribe to; here it shows the saving notice once per visit.
Guarded storage access
Reading or writing localStorage can throw (private browsing, blocked storage); the try/catch turns that into null so the game falls back to memory.
