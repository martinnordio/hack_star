# Spec kit of Hack star

Generated by spec-nx `ec52844` (v0.3.3) with Claude Opus 5.5 on 2026-11-14. Do not edit the
files in this folder by hand: `GENERATE KIT --update` replaces them. Project rules go into
`.specs/guidelines/`; the game's specs into `.specs/features/`; the overall game idea is in
`.specs/overall_req.md`.

## How to use a stage

In the AI chat of your editor, load the stage prompt and type its command:

```
Load .specs/kit/<stage>/prompt.md.
<COMMAND>: <arguments>
```

## The workflow

One feature = one spec = one branch `feature/<name>` = one pull request on GitHub. Every
commit message carries the spec's issue reference (`#<n>`) — `guidelines/commits.md`.

| # | Stage | Command | Result |
|---|-------|---------|--------|
| 1 | requirements | `REQUIREMENTS: <name> — <what you want>` | Part 1 of `.specs/features/<date>_<name>_spec.md`; answer its open questions with `REQUIREMENTS: <spec file> — <answers>` |
| 2 | plan | `PLAN: <spec file>` | Part 2: Steps, decisions, Definition of Done |
| 3 | implementation | `IMPLEMENT: <spec file>` — once per Step, commit after each | Code in `server/` and `ui/` + the Step marked done |
| 4 | review | `REVIEW: <spec file>`, `CODE REVIEW: <spec file>` | Semantic diff for the pull request; findings in the Review Log |
| 5 | implementation | `CLOSE: <spec file>` | Spec moved to `.specs/features/done/` |
| 6 | pr | `PR: <spec file>` | Pull request and issue updated with the spec summary |

## Models and cost

- **Models** (`models.md`): fixed — Claude Opus 5.5 for every stage and Step. Each stage
  checks its model first and runs as a sub-agent on it where the tool allows. Change it in
  `.specs/spec-nx.json` (`models`), or only for you in `.specs/spec-nx.local.json` (`null` =
  always your tool's model).
- **Tokens and cost** (`COSTS.md`): every Stage log row and Done line gets its tokens and cost
  in CHF (Copilot Business); `CLOSE:` adds a cost summary and rebuilds `.specs/costs.md`.
  **All costs are estimates and may be wrong.** Turn it off with `"enabled": false` in the
  `cost` block.

## Now and then

| Command | Stage | Does |
|---------|-------|------|
| `CREATE ISSUE: <spec file> [parent <n>]` | requirements | Creates the spec's GitHub issue (optionally a sub-issue of a parent); offered when the requirements are finished |
| `UPDATE ISSUE: <spec file>` | requirements | Summary of the spec into its issue |
| `GUIDELINES: <language>` | guidelines | Writes or updates `.specs/guidelines/<language>.md` (python, typescript, svelte, powershell) |

## Settings

- `.specs/spec-nx.json` — the team's answers (committed).
- `.specs/spec-nx.local.json` — your settings, e.g. your shell (not committed).
- Update the kit: `git submodule update --remote .spec-nx`, then load
  `.spec-nx/generator/prompt.md` and run `GENERATE KIT --update`.
